# V1.1 workflows

## Mechanical recipes

Compile a reviewed JSON recipe into the ordinary V1 job manifest with `omnicad mechanical`. The compiler creates standard editable DXF geometry, not a mesh or a machining model. Continue with `build` and `audit`. The examples are complete input documents.

- [Shaft A](../examples/shaft-a.json) shows flat keyway ends, aligned plan/left views, both end chamfers and two shoulder fillets.
- [Flange B](../examples/flange-b.json) shows the plan, front and section through the first and opposite bolt positions. It uses an even bolt count, a supplied phase and PCD, and four independent material hatch regions. The example uses a textual angular-spacing annotation derived from the equally spaced bolt count.
- [Shaft C](../examples/shaft-c.json) shows the threaded end, a transverse keyway section and a local axial section, fit designations, circular runout against a datum, machining-required surface texture symbols, and explicit centre-hole designations.

Lengths are millimetres. Booleans `plan`, `left_view`, and `local_section` select the supplied views. Shaft land references are one-based, and a shoulder fillet `after` refers to the preceding land. The keyway starts at an absolute X station. A keyway plan requires a confirmed supported `ends: "flat"` form; leave it absent if unknown and use the section views. Threads use the conventional external root/crest representation and a geometric clearance check; the recipe does not assign a tolerance class or a runout/relief tooling dimension. End chamfers are 45°; explicit left/right values are the leg lengths. For standard centre holes, supply a verified designation. The view scale is optional and defaults to 1. Check that the views and symbols fit the A3 layout when using other dimensions.

The ordinary job manifest also accepts `hatch` (one closed sequence of line/CCW arc edges, ANSI31), `triangle` (three points), and `runout` (insertion point, value and datum letter). A linear dimension can add a diameter prefix and optional fit with a `display` like `%%c<> h6`. The measured value remains native and is audited separately.

## Scope and revision evidence

    omnicad intent request.txt --reference reference.pdf --target plan.dwg --region "Room A" \
      --preserve "Walls and grids" --constraint "Existing openings only" --report scope.json

The local phrase rules preserve the original brief and distinguish reference, target, region, constraints and missing decisions. Treat extracted clauses as review candidates. An ambiguous swap records a hold until both features and the intended exchange are supplied. If the target is the original DWG, work on its native copy and take same-lineage before/after DXF readbacks.

    omnicad diff before.dxf after.dxf --allowlist allowed.json --report delta.json

The JSON allowlist uses reported identities such as `"Model:label-id"` and `"Model:@2D6"` for tagged and untagged geometry. Layouts, symbol/block definitions and shared drawing tables also appear in the comparison. Same-lineage readbacks matter because unrelated exporters can rekey handles. The existing `revise` command checks the pre/post scope automatically and records the changed identities alongside its backup. Native DXF readback comparison does not certify every proprietary DWG object, project reference or design constraint.

## OQA levels

| Mode | Use | Checks |
|---|---|---|
| light | Default for routine DXF jobs | DXF structure, native model entity types, internal drawing text and explicitly supplied PDF structure |
| standard | Discipline review | Adds optional reviewed geometry manifest, role expectations, text encoding/styles and duplicate dimensions |
| full | Native delivery and independent audit preparation | Adds available native reopen/edit evidence, Poppler render, and independent DWG replot comparison |

    omnicad publish job.json drawing.dxf publication --verify-native
    omnicad oqa publication/readback.dxf --job job.json --domain mechanical --mode full \
      --publication publication/report.json --expect-text "M24×1.5" --report qa.json

Use `--contract role-checks.json` for reviewed assessments of existing drawings. Supported role groups include walls/openings/axes/dimensions for architecture, geometry/elevations/axes/sections/components for civil, and profile/dimensions/annotations/sections for mechanical. A contract role contains one or more exact expectations:

    {"elevations": [{"layer":"LEVEL","type":"TEXT","count":1,"field":"text","values":["+0.000"]}]}

Optional numeric fields are length on lines, radius on circles/arcs, and measurement on dimensions. A manifest can check reviewed coordinates and dimensions. Unattached roles, observed font appearance, document completeness and functional engineering decisions remain manual. PDF text matching is explicit and extracted reading order can differ on rotated text. The report separates automated, AutoCAD and manual rows, retains missing evidence, and reports covered checks instead of a professional grade. The CLI uses no model calls and records wall time. `--metrics` can attach measured orchestration data. Unknown token usage remains null.

Publication exit code 2 can mean a legitimate hold for required visual evidence. Native proof is tied to the publication artifact hashes. Capture separate visual evidence after reviewing the exact DWG/PDF and use `audit --publication ... --review ...` for the manifest gate. Check failures return exit code 2 in `oqa`; inspect the JSON for unverified items even when the command exits successfully.

## AutoCAD PDF catalog repair

AutoCAD's tested print driver can write two top-level `/PageMode` keys. V1.1 retains `raw-plot.pdf` and delivers a strictly parsed `sheet.pdf` when the known duplicate is detected. The repair preserves the first viewer-mode entry and replaces the later entry with spaces. It preserves byte offsets and page contents, including text, vectors, layers and outlines. Some viewers may open a different navigation pane. Other structural problems, encryption and signatures are outside this repair. The standalone `repair-pdf raw.pdf clean.pdf` command uses a fresh path.

Native opening, editing and PDF checks require licensed AutoCAD on Windows plus `[intake,autocad]`. PNG rendering needs Poppler; isolated DXF geometry does not need it.
